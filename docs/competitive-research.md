# Pi-Go Desktop v0.1 — 竞品调研与差距分析报告

> 生成日期：2026-05-22
> 调研范围：Cursor、Claude Desktop、ChatGPT Desktop、GitHub Copilot、Windsurf、Lobe Chat、Continue.dev 等

---

## 一、Executive Summary（三大改进方向）

基于对主流 AI 编程助手和通用 AI Chat 桌面应用的调研，pi-go 当前状态是一个**最小可用的 AI Chat 界面 + Agent 后端**，在「编程辅助深度」和「桌面原生体验」两个维度上存在显著差距。以下是优先度最高的三大方向：

| 优先级 | 方向 | 预期效果 |
|--------|------|----------|
| **🔥 P0** | **编辑器集成 + 代码上下文感知** | 从通用 Chat 升级为真正理解用户代码库的助手 |
| **🔥 P0** | **对话交互增强**（编辑/重试/分叉/历史搜索） | 大幅降低用户试错成本，提升对话利用率 |
| **🔥 P1** | **桌面原生体验打磨**（快捷键/托盘/通知/全局窗口管理） | 从"网页套壳"感觉到"真正桌面应用" |

## 三、功能差距分析（P0 / P1 / P2）

### 🔴 P0 — Must Have（对编程助手场景最核心的缺失）

#### 1. 对话交互增强

| 功能 | 用户价值 | 覆盖率 |
|------|---------|--------|
| **消息编辑 + 重新发送** | Agent 写了一半或写错时，用户可以直接修改 prompt 而不必重新开 session。日常使用频率极高。 | 所有用户，每次对话 |
| **重新生成（Regenerate）** | 对不满意的回答一键换新。零成本试错。 | 所有用户，高频 |
| **消息复制（一键复制代码块）** | 复制代码到别的工具是编程助手的核心操作。目前只能手动选中。 | 所有用户，极高频率 |

#### 2. 文件上下文引用 (@file / @folder)

| 功能 | 用户价值 | 覆盖率 |
|------|---------|--------|
| **@ 触发文件选择器** | 用户需要让 AI 理解特定代码文件时，@ 是最自然的交互范式。没有这个功能，用户只能手动粘贴代码。 | 所有用户，每天数十次 |
| **文件内容自动打包发送** | 选中文件后自动读取内容、附加上下文，不需要用户自行复制粘贴。 | 所有用户 |
| **拖拽文件到输入区** | 比 @ 更直觉的操作方式，尤其是非代码文件（图片、PDF）。 | 所有用户 |

#### 3. 代码块交互

| 功能 | 用户价值 | 覆盖率 |
|------|---------|--------|
| **代码块右上角复制按钮** | 当前生成代码后用户需要用鼠标选中再复制。一个小按钮能省 80% 的操作成本。 | 所有用户，极高频率 |
| **代码语言标签** | 让用户一眼知道生成的是什么语言。 | 所有用户 |
| **代码展开/折叠** | 长代码块默认折叠，保持对话可读性。 | 长输出场景 |

### 🟡 P1 — Important（显著提升用户体验和效率）

#### 4. Session 管理增强

| 功能 | 用户价值 | 覆盖率 |
|------|---------|--------|
| **Session 重命名（双击标题）** | 当前 session 以 UUID 或空显示，用户无法快速识别对话内容。自动/手动重命名是基本功能。 | 所有用户 |
| **Session 搜索** | session 多到一定数量后，没有搜索 = 找不到历史对话。 | 重度用户 |
| **Session pinning（置顶）** | 固定重要对话到列表顶部。 | 重度用户 |

#### 5. Agent 可视化增强

| 功能 | 用户价值 | 覆盖率 |
|------|---------|--------|
| **Token 用量显示** | 用户需要知道自己用了多少 token（尤其是付费 API 场景），也是排查输出截断的重要参考。 | API 自备 key 的用户 |
| **执行耗时展示** | Agent 执行的每个步骤耗时多少，帮助用户判断"卡住了还是正在工作"。 | 所有用户 |
| **Tool call 实时状态流式更新** | 当前 tool call 完成后才显示结果，如果能在执行中逐步显示会更透明。 | 所有用户 |

#### 6. 桌面原生体验

| 功能 | 用户价值 | 覆盖率 |
|------|---------|--------|
| **全局快捷键**（Cmd+K / Cmd+Shift+K） | 用户可以在任何应用中一键唤出 pi-go 窗口，是桌面客户端对比网页版的核心价值。 | 所有用户 |
| **系统托盘** | 关闭窗口后应用继续在后台运行，不中断 Agent 任务。 | 长时间使用用户 |
| **窗口位置/大小记忆** | 每次打开恢复到上一次的位置和大小，不打断工作流。 | 所有用户 |
| **Dock Badge**（未读消息数） | macOS Dock 图标上显示正在执行的任务状态或未读。 | macOS 用户 |

#### 7. 模型与配置

| 功能 | 用户价值 | 覆盖率 |
|------|---------|--------|
| **系统提示词编辑器** | 高级用户需要自定义 system prompt 来控制 AI 行为风格。 | 高级用户 |
| **Model 参数调节**（temperature, max_tokens） | 对精确/创造模式切换有需求的高级用户。 | 高级用户 |
| **Provider 健康度指示** | 当前 API 不可用时给用户明确反馈，而不是 timeout 后报错。 | 所有用户 |

### 🟢 P2 — Nice to Have（锦上添花，后期再补）

| 功能 | 用户价值 |
|------|---------|
| 语法高亮主题切换 | 代码块显示风格跟随用户偏好 |
| 数学公式渲染 (LaTeX) | 技术文档场景 |
| 对话分叉 (fork) | 从某一条消息分支出新分支探索不同方案 |

| Prompt 模板库 | 预设常用 prompt |
| Session 分组/标签 | 大量 session 时的组织需求 |
| 截图粘贴 | 快速分享报错截图 |
| Markdown 预览（split view） | 写文档场景 |

## 四、UX 改进建议（按交互场景）

### 场景 1：开始新对话

**当前痛点：**
- 用户进入应用 → 看到空面板 → 需要手动点 "New Session" → 然后开始打字

**建议改进：**
1. 空态提供"快速开始"模板：修复 bug / 解释代码 / 代码审查 / 自由对话
2. Session 列表自动以对话第一句话命名（或 AI 摘要生成标题）
3. @ 文件选择器：输入 @ 后弹出一个命令面板（类似 VS Code Cmd+Shift+P）
4. 欢迎页显示最近 session + 快捷动作

> 参考：Cursor 的欢迎页有最近文件 + 最近 session + 快捷 action 入口。Claude Desktop 的 @ 触发非常顺滑。

### 场景 2：Agent 执行中

**当前痛点：**
- 等待时只有一个 spinner，用户不知道 Agent 在做什么
- 长时间运行的工具调用（如 bash build）没有进度反馈
- 无法在 Agent 思考时插入新的指令

**建议改进：**
1. Tool call 列表实时更新（进入 thinking → 执行中 → 完成）
2. 耗时较长的 tool call 显示进度条或 spinning dots
3. 允许在 Agent 执行时发送"干预消息"（interrupt + 追加指令）
4. Streaming 光标用打字机效果（已有部分实现），但增加段落间淡入动画

> 参考：Cursor Agent 模式下，每个 tool call 有独立的状态卡片，点开可看完整输出，折叠时只看摘要。

### 场景 3：查看与复用历史回答

**当前痛点：**
- 消息不能编辑，打错字只能重开 session
- 不能重新生成回答
- 不能复制代码块（需要手动选中）
- 没有消息搜索

**建议改进：**
1. 每条消息 hover 出现操作栏：复制 / 编辑 / 重新生成 / 删除
2. 代码块右上角固定"复制"按钮 + 语言标签
3. 编辑消息后自动重新发送（不需要用户再点发送按钮）
4. Cmd+F 在对话内搜索文本

> 参考：ChatGPT Desktop 的 hover 工具栏做得非常成熟。Claude Desktop 编辑消息后自动 regenerate。

### 场景 4：切换与管理 Session

**当前痛点：**
- Session 列表只显示创建时间，无法快速区分内容
- 没有搜索或过滤
- 没有 pinning 功能
- 删除 session 后没有撤销

**建议改进：**
1. 自动以首条消息命名 session（AI 生成摘要标题更佳）
2. 列表支持双击重命名
3. 搜索框过滤 session 列表（按标题/内容模糊匹配）
4. 右键菜单：重命名 / 置顶 / 删除 / 导出
5. 删除 session 后 toast 提示 "已删除" + "撤销"按钮

### 场景 5：窗口与多任务

**当前痛点：**
- 关闭窗口 = 退出应用
- 没有全局快捷键
- 窗口位置每次重置
- 长时间 Agent 任务无法在后台运行

**建议改进：**
1. 关闭窗口行为改为隐藏（macOS hide）/ 最小化到托盘（Win）
2. 注册全局快捷键（CMD+K 唤出 / CMD+Shift+K 快速提问）
3. 窗口关闭时保存位置和大小到本地存储
4. 系统托盘图标：正在执行时显示动画，完成后弹出通知
5. macOS Dock 图标 badge 显示运行状态

## 五、技术实现参考 & 开源替代

### 5.1 React 生态（与现有 CSS Modules + CSS Variables 兼容）

| 需求 | 推荐方案 | 理由 |
|------|---------|------|
| **编辑器集成 / 代码上下文** | Continue.dev 开源方案 | Continue 是开源 Code AI 插件，其 @ 文件引用、代码上下文提取等逻辑可直接参考 |
| **@ 命令面板** | cmdk (~1.2MB) 或自己用 Input + Dropdown 实现 | cmdk 轻量、无障碍好。已有 CSS Variables 主题化 |
| **代码块复制按钮** | 纯 CSS + React state，不需要第三方库 | 每行代码的功夫 |
| **虚拟滚动** | react-virtuoso (~30KB) 或 @tanstack/virtual (~6KB) | 长对话列表性能优化。react-virtuoso 自带 scroll-to-bottom |
| **Markdown 扩展** | remark-gfm + rehype-katex (数学公式) | 兼容现有 react-markdown 生态 |
| **预览/高亮增强** | shiki (~5MB, 按需加载) 或 prismjs (~8KB gzip) | shiki 比 highlight.js 更现代但更大。权衡后保留 highlight.js 加主题切换 |
| **Toast 通知** | sonner (~3KB) 或自己写 | 轻量，主题跟随 CSS Variables |
| **拖拽文件上传** | react-dropzone 或原生 HTML5 drag/drop | 不需要大库，react-dropzone 封装较完善 |
| **全局快捷键** | Electron globalShortcut API（已有能力） | 不需要 npm 包，直接使用 Electron 内置 API |
| **右键菜单** | @radix-ui/react-context-menu 或自己实现 | Radix 无障碍好，样式通过 CSS Modules 自定义 |

### 5.2 架构级建议

```
                            v0.1 → v0.2 架构演进

  1. 代码上下文层（新增）
     pi-go-desktop/
     └── src/
         ├── context/                    ← 新增
         │   ├── FileContextProvider.ts    @文件选择器 + 读取
         │   ├── FileSearch.ts           文件模糊搜索
         │   └── ContextPacker.ts        上下文打包（发送给后端）

  2. 增强的 Store 层
         ├── stores/
         │   ├── uiStore.ts              ← 新增（窗口状态/托盘）
         │   └── settingsStore.ts        ← 新增（用户偏好持久化）

  3. 现有的 WebSocket 协议扩展
     Client → Server: 新增 event 类型
       - "context_update"   // 发送文件上下文
       - "interrupt"        // 干预正在执行的 Agent
     Server → Client: 新增 event 类型
       - "progress"         // 长时间任务的进度反馈
       - "token_usage"      // token 消耗报告
```

### 5.3 Go 后端扩展思路

| 功能 | 实现路径 |
|------|---------|
| @ 文件引用 | 前端解析 @ 语法 → 读取文件内容 → 附加到 prompt 上下文中发送。后端不需要修改。 |
| Token 用量统计 | 后端在每次 turn_end 事件中附加 `token_usage` 字段。前端 chatStore 存储并展示。 |
| Agent 干预 | WebSocket 新增 `interrupt` 消息类型，后端收到后停止当前 tool 循环并处理新 prompt。 |
| 进度反馈 | 长时间 tool 返回中间状态（如 bash 执行中周期发送 stdout）。 |

## 总结

pi-go 的架构基础（Electron + React + Go Agent 后端 + WebSocket 实时通信）是**健康的、可扩展的**。当前最大的差距不在技术架构上，而在于**交互范式的完成度**。

快速赢取用户心（v0.2）的核心路径：

> **让用户能方便地引用文件（@）+ 方便地复制代码 + 方便地修正对话（编辑/重试）**

这三个能力加起来，对于一个 AI 编程助手而言，不是锦上添花，而是**生存基线**。
